# 数据库-接口契约（前端对接用）

> 对应数据库脚本：[`supabase/init.sql`](../supabase/init.sql)
> 对应前端数据层：`src/lib/api.ts`、`src/types/db.ts`
> 依据：`docs/设计方案.md` v2.5 第 10–12 节 + 本次简化口径；执行说明见 [`supabase/README.md`](../supabase/README.md)
>
> **本文件是前后端的唯一接口约定。** 前端只能使用下面列出的表 / 列 / RPC；返回列名与顺序以本文件为准。
> 数据库侧已把「RLS + 列级 GRANT + RPC」三层防线全部落地，前端隐藏按钮不算安全，越权动作必须由数据库拦住。

## 0. 总原则（先看这一节）

### 0.1 连接

```ts
// .env.local（只放 anon key，绝不能出现 service_role）
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
```

```ts
import { createClient } from '@supabase/supabase-js'
export const supabase = createClient(
  import.meta.env.VITE_SUPABASE_URL,
  import.meta.env.VITE_SUPABASE_ANON_KEY,
  { auth: { persistSession: true, autoRefreshToken: true } },
)
```

### 0.2 三层防线（前端必须理解，否则会误判「为什么写不进去」）

| 层 | 作用 | 前端感知 |
|---|---|---|
| RLS（行级） | 能看 / 能改**哪些行** | 查不到的行直接消失；改别人的行返回 0 行 |
| 列级 GRANT | 能读写**哪些列** | 越权列 → `42501 permission denied for table ...` |
| RPC（security definer） | 复杂动作的原子性与合法性 | 失败时抛中文异常，前端直接展示 `error.message` |

### 0.3 硬性约定

1. **`profiles` 永远不要 `select('*')`**：普通用户只能读 `id, display_name, avatar, bio, created_at` 五列，`select('*')` 会 `42501`。管理员用户列表请用视图 `admin_profiles`（见 1.12）。
2. **所有计数列只读**（`like_count / dislike_count / comment_count / favorite_count`、`follows` 等），只能由 RPC / 触发器维护；前端直接 `update` 会 42501。
3. **明细表禁止直写**：`post_votes`、`favorites`、`follows`、`user_handles` 连 INSERT 权限都没有，只能走 RPC。
4. **删除是软删除**：没有物理 DELETE 权限；调 `soft_delete_post` / `soft_delete_comment`。
5. RPC 失败统一 `raise exception '中文提示'`，前端**直接展示 `error.message`**（下面每节的「错误」列了具体文案）。
6. `returns table(...)` 的 RPC 在 PostgREST 里返回**数组**（即使只有一行）；单行语义用 `data[0]`。`returns void` 的 RPC 返回 `data = null`。
7. 分页 `range(from, to)` 是**闭区间**；`limit` 是条数。RPC 分页建议取 `limit + 1` 判断 `hasMore`（本文件所有分页 RPC 都按这个约定写）。
8. 时间字段一律 ISO 8601 字符串（`timestamptz`），前端用 `new Date(...)` 解析。

## 1. 表结构：前端可读 / 可写列

> 未列出的列 = 前端**读不到或写不了**（数据库已收回权限）。
> 「可直写」= PostgREST 直接 `insert/update` 允许；其余只能通过 RPC / 触发器。

### 1.1 `profiles`（用户资料，公开可读）

| 列 | 类型 | 可读 | 可直写 | 说明 |
|---|---|---|---|---|
| `id` | uuid | ✅ 公开 | ❌ | 与 `auth.users.id` 相同，作者主页路径 `#/u/:id` |
| `display_name` | text | ✅ 公开 | ✅ | 2–20 字符，公开显示 |
| `avatar` | text | ✅ 公开 | ✅ | 头像预设 id，如 `avatar-1` |
| `bio` | text | ✅ 公开 | ✅ | ≤ 200 字符 |
| `created_at` | timestamptz | ✅ 公开 | ❌ | |
| `role` / `is_active` / `banned_reason` / `banned_until` | — | ❌ | ❌ | 仅本人经 `my_profile()`、管理员经 `admin_profiles` 视图可见 |
| `updated_at` | timestamptz | ❌ | ❌ | 仅 `my_profile()` 返回 |

```ts
// ✅ 公开资料（例如嵌入查询或作者主页兜底）
supabase.from('profiles')
  .select('id, display_name, avatar, bio, created_at')
  .eq('id', userId).maybeSingle()

// ✅ 改自己的资料（只允许这 3 列；role/is_active 改不了）
supabase.from('profiles')
  .update({ display_name, avatar, bio })
  .eq('id', userId)

// ❌ 会 42501：supabase.from('profiles').select('*')
```

### 1.2 `user_handles`（用户名句柄，**不公开**）

| 列 | 类型 | 可读 | 可直写 |
|---|---|---|---|
| `id` / `user_id` / `username` / `is_current` / `released_at` / `created_at` | — | ✅ 仅本人 / 管理员 | ❌ |

- RLS：只能读到 `user_id = auth.uid()` 的行（管理员可读全部）。
- 注册时由触发器写入；前端不改、不公开。**写入时校验违禁词**（命中「用户名包含违禁词…」）。个人中心显示 `@username`：

```ts
supabase.from('user_handles')
  .select('username, is_current')
  .eq('user_id', userId).eq('is_current', true).maybeSingle()
```

> 别人的 username 拿不到（`[]` 或 RLS 过滤），这是设计如此：username 是登录凭据之一，不公开。

### 1.4 `posts`（帖子，公开可读）

| 列 | 类型 | 可读 | 可直写（insert） | 可直写（update） |
|---|---|---|---|---|
| `id` | uuid | ✅ | ❌（自增默认） | ❌ |
| `board_slug` | text | ✅ | ✅ | ❌ |
| `author_id` | uuid | ✅ | ❌（触发器填 `auth.uid()`） | ❌ |
| `title` | text | ✅ | ✅ | ✅ |
| `content` | text | ✅ | ✅ | ✅ |
| `images` | text[] | ✅ | ✅（当前不传图片） | ✅ |
| `like_count` / `dislike_count` / `comment_count` / `favorite_count` | int | ✅ | ❌ | ❌ |
| `is_pinned` / `is_locked` / `is_deleted` | boolean | ✅ | ❌ | ❌ |
| `created_at` / `updated_at` | timestamptz | ✅ | ❌ | ❌ |

- 前端可见性：`is_deleted = false`（作者本人、管理员可按 RLS 看到已删）。
- 列表默认过滤 `is_deleted = false`；管理员后台不筛，能看到全部（含已删，用于删帖复查）。
- 长度约束：标题 2–80、正文 1–5000；违反返回 `23514`（约束名 `posts_title_len` / `posts_content_len`）。
- **违禁词校验**：发帖/改帖时触发器检查 `title` + `content`，命中返回 `22000` + 「标题/正文包含违禁词「xx」，请修改后再提交」。

```ts
// 发帖（author_id 由触发器填，不要传；images 建议传 [] 或省略）
supabase.from('posts')
  .insert({ board_slug, title, content, images: [] })
  .select(POST_SELECT).single()

// 改自己的帖子（只能改 title/content/images）
supabase.from('posts').update({ title, content }).eq('id', postId)
```

### 1.5 `comments`（评论）

| 列 | 类型 | 可读 | 可直写（insert） | 可直写（update） |
|---|---|---|---|---|
| `id` | uuid | ✅ | ❌ | ❌ |
| `post_id` | uuid | ✅ | ✅ | ❌ |
| `author_id` | uuid | ✅ | ❌（触发器填） | ❌ |
| `parent_id` | uuid | ✅ | ✅（二期楼中楼，当前传 null / 省略） | ❌ |
| `content` | text | ✅ | ✅ | ✅ |
| `is_deleted` | boolean | ✅ | ❌ | ❌ |
| `like_count` | int | ✅ | ❌ | ❌（只能 `toggle_comment_like`，见 4.24） |
| `created_at` / `updated_at` | timestamptz | ✅ | ❌ | ❌ |

- 可读条件：评论未删（作者/管理员例外）且所属帖子对当前用户可见。

- 删评论：调 RPC `soft_delete_comment`，`comment_count` 自动 -1。

### 1.12 `admin_profiles`（视图，**仅 admin 可见**）

> 用途：管理后台「用户」标签。因为 `profiles` 的 `role / is_active / banned_*` 对普通用户是列级禁读的，
> 管理员改从这个视图读；视图内部用 `where public.is_super_admin()` 做行过滤。
> **非 admin 查询返回 `[]`（不报错）**；moderator 也是 `[]`（按设计，用户管理仅 admin）。

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | uuid | 用户 id |
| `display_name` | text | 昵称 |
| `avatar` | text | 头像 |
| `bio` | text | 简介 |
| `role` | `user_role` | `user` / `moderator` / `admin` |
| `is_active` | boolean | 是否启用（封禁时为 false） |
| `banned_reason` | text | 封禁原因 |
| `banned_until` | timestamptz | 临时封禁到期时间，NULL = 永久 |
| `created_at` / `updated_at` | timestamptz | |
| `username` | text | 当前句柄（管理后台展示 `@handle`） |
| `post_count` / `comment_count` / `follower_count` | bigint | 计数（不含已删内容，粉丝数） |

```ts
// 管理员用户列表（关键：表名是 admin_profiles，不是 profiles）
supabase.from('admin_profiles')
  .select('*')
  .order('created_at', { ascending: false })
  .limit(100)
// 搜索：.ilike('display_name', `%${keyword}%`)
// 分页：.range(from, to)；总数：{ count: 'exact' }
```

### 1.14 `banned_words`（违禁词库，**前端完全不可见**）

| 列 | 类型 | 可读 | 可直写 |
|---|---|---|---|
| `id` / `word` / `note` / `created_by` / `created_at` | — | ❌（无 SELECT 权限，列表走 `admin_banned_words`） | ❌（只能 `admin_*` RPC） |

- 匹配规则：统一小写、去掉所有空白（含全角空格），**包含即命中**；多个词命中时返回最长那个（`find_banned_word`）。
- 生效位置（数据库触发器，前端绕不过去）：
  - 发帖 / 改帖：`posts.title` + `posts.content`
  - 评论 / 改评论：`comments.content`
  - 昵称：`profiles.display_name`（注册和个人中心改名都覆盖）
  - 用户名：`user_handles.username`
- 命中统一返回 `22000` + 「标题/正文/评论内容/昵称/用户名包含违禁词「xx」，请修改后再提交」。
- 匿名可用 `check_banned_word(text)` 预校验（注册昵称前先查）；管理接口见 4.26 ~ 4.28。
- 种子词：傻逼 / 煞笔 / 操你妈 / fuck / 代开发票 / 赌博网站 / 黄色网站 / 办假证 / 冰毒（后台可增删）。

### 1.15 `feedback`（意见反馈，**前端完全不可直读写**）

| 列 | 类型 | 可读 | 可直写 |
|---|---|---|---|
| `id` / `user_id` / `category` / `content` / `contact` / `status` / `handled_by` / `handled_at` / `created_at` | — | ❌（无表权限；自己的走 `my_feedback`，管理端走 `admin_feedback`） | ❌（只能 `submit_feedback` / `admin_resolve_feedback`） |

- 用途：用户提建议 / 问题 / 其他，管理员在「管理后台 → 反馈」查看并标记处理。
- 字段约束：`content` 5–1000 字、`category` 1–10 字（默认 `建议`）、`contact` ≤100 字（可空）、`status` 只有 `pending` / `resolved`。
- 隐私：联系方式属于隐私字段，表级无 SELECT 权限 + 开启 RLS 且不建策略 → 直连 REST 一律被拒。
- 内容同样过**违禁词触发器**（命中报 `22000` +「反馈内容包含违禁词「xx」…」）。
- 被限制（封禁 / 临时封禁中）的账号不能提交，报 `42501` +「账号当前无法操作」。

### 1.16 `friendships`（好友关系，**前端完全不可直读写**）

单向存储：A 加 B 成功会写两条（A→B、B→A）。A 删好友只删自己那条，B 那边还在 → `pair_state` 返回 `half`。

| 列 | 类型 | 说明 |
|---|---|---|
| `user_id` | uuid | 归属者（PK 之一） |
| `friend_id` | uuid | 好友（PK 之二） |
| `status` | text | `friend` / `blocked`（我拉黑了他） |
| `since` | timestamptz | 成为好友的时间 |

约束：`no_self_friend`（不能加自己）、`friendships_status_chk`。读写只走 RPC。

### 1.17 `friend_requests`（好友申请，**前端完全不可直读写**）

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | uuid | 申请 id |
| `from_id` | uuid | 申请人，默认 `auth.uid()` |
| `to_id` | uuid | 被申请人 |
| `message` | text | 留言，≤100 字（过违禁词） |
| `status` | text | `pending` / `accepted` / `rejected` |
| `created_at` / `handled_at` | timestamptz | 发起 / 处理时间 |

同一对用户同时只允许一条 `pending`（部分唯一索引 `friend_requests_pending_idx`），重复点「加好友」会覆盖留言。

### 1.18 `conversations`（私信会话，**只读自己参与的；写只能走 RPC**）

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | uuid | 会话 id |
| `user_a` / `user_b` | uuid | 两个参与者，**强制 `user_a < user_b`** |
| `last_seq` | int | 会话内最新消息序号（发送时 +1） |
| `last_at` | timestamptz | 最后一条消息时间，用于会话列表排序 |

> **授权**：`authenticated` 只有 `SELECT`（策略 `conversations_select_participant` 限制为参与者），没有任何写权限；`anon` 一律拒绝。SELECT 是 Supabase Realtime 订阅的前提。

## 2. PostgREST 嵌入查询：外键默认名（**不要改**）

外键都用 PostgreSQL 默认名（建表时没有自定义 constraint 名），前端嵌入查询必须用这些 `!fk_name` 提示：

| 起点表 | 目标表 | 嵌入写法（示例） |
|---|---|---|
| `posts` | `profiles` | `author:profiles!posts_author_id_fkey(id, display_name, avatar, bio, created_at)` |
| `comments` | `profiles` | `author:profiles!comments_author_id_fkey(id, display_name, avatar, bio, created_at)` |
| `comments` | `posts` | `post:posts!comments_post_id_fkey(id, title)` |
| `notifications` | `profiles` | `actor:profiles!notifications_actor_id_fkey(id, display_name, avatar, bio, created_at)` |
| `notifications` | `posts` | `post:posts!notifications_post_id_fkey(id, title)` |
| `favorites` | `posts` | `post:posts!favorites_post_id_fkey(...)` |
| `reports` | `profiles` | `reporter:profiles!reports_reporter_id_fkey(id, display_name, avatar)` |
| `post_votes` | `profiles`（不常用） | `user:profiles!post_votes_user_id_fkey(...)` |
| `follows` | `profiles`（两个 FK，必须写提示） | `target:profiles!follows_target_id_fkey(...)` / `follower:profiles!follows_follower_id_fkey(...)` |

统一常量（与 `src/lib/api.ts` 一致）：

```ts

  '*, author:profiles!posts_author_id_fkey(id, display_name, avatar, bio, created_at)'
```

## 3. 常用查询示例

### 3.1 帖子列表（最新 / 最热 / 板块筛选 / 分页）

```ts
const PAGE_SIZE = 10
let q = supabase
  .from('posts')
  .select(POST_SELECT, { count: 'exact' })
  .eq('is_deleted', false)

if (board) q = q.eq('board_slug', board)

// 时间筛选（可选，左闭右开）：used for 今天 / 近 7 天 / 自定义日期区间
if (since) q = q.gte('created_at', since)
if (until) q = q.lt('created_at', until)

if (sort === 'hot') {
  q = q.order('is_pinned', { ascending: false })
       .order('like_count', { ascending: false })
       .order('created_at', { ascending: false })
} else {
  q = q.order('is_pinned', { ascending: false })
       .order('created_at', { ascending: false })
}

const rows = await q.range(offset, offset + PAGE_SIZE) // 多取 1 条判断 hasMore
// rows.length > PAGE_SIZE → 还有下一页
```

> 迁移与回填数据后，如果要「翻页不重复」，也可以改用 keyset 分页（`created_at` + `id` 游标）；本版先用 range。

## 4. RPC 契约

> 所有 RPC 都是 `security definer + set search_path = public`，函数体内再校验一次权限。
> `returns table(...)` → `data` 是数组；`returns void` → `data = null`。
> 失败时 `error.message` 是中文提示，直接展示给用户（可按第 5 节做兜底映射）。

### 4.1 `username_available`

`username_available(p_username text) returns boolean` —— **匿名可调**

| 入参 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `p_username` | text | 是 | 会先 `trim + lower` 再校验 |

| 返回 | 类型 | 说明 |
|---|---|---|
| `boolean` | boolean | `true` = 格式合法且可用；`false` = 格式不合规 / 已被占用 / 90 天内被释放过 |

```ts
const { data, error } = await supabase.rpc('username_available', { p_username: name })
```

规则：`^[a-z0-9_]{3,20}$`（前端先转小写再调）。注册是「邮箱 + 昵称 + 密码」，用户名可选；
不传或不可用时，触发器会自动生成 `u_ + 8 位十六进制` 的句柄，**不会导致注册失败**。

### 4.2 `search_posts`

`search_posts(p_query text, p_board text default null, p_sort text default 'new', p_limit int default 20, p_offset int default 0, p_since timestamptz default null, p_until timestamptz default null)`

**匿名可调** · 返回 16 列（作者昵称/头像直接带回，不用二次查询）

| 入参 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `p_query` | text | 无（必传） | 空 / 空白字符串 → 返回空数组，前端不应发请求 |
| `p_board` | text | null | 板块 slug，null = 全部板块 |
| `p_sort` | text | `'new'` | `'new'` = 时间倒序；`'hot'` = `like_count` 倒序 |
| `p_limit` | int | 20 | 1–50（超出自动截断） |
| `p_offset` | int | 0 | 偏移 |
| `p_since` | timestamptz | null | 起始时间（含）：只返回 `created_at >= p_since`；null = 不限 |
| `p_until` | timestamptz | null | 结束时间（不含）：只返回 `created_at < p_until`；null = 不限 |

返回列（顺序固定）：

| # | 列名 | 类型 | 说明 |
|---|---|---|---|
| 1 | `id` | uuid | 帖子 id |
| 2 | `board_slug` | text | 板块 |
| 3 | `author_id` | uuid | 作者 id |
| 4 | `title` | text | 标题 |
| 5 | `content` | text | 正文（前端自行截断做摘要） |
| 6 | `images` | text[] | 当前恒为 `[]` |
| 7 | `like_count` | int | |
| 8 | `dislike_count` | int | |
| 9 | `comment_count` | int | |
| 10 | `favorite_count` | int | |
| 11 | `is_pinned` | boolean | 置顶（排序优先） |
| 12 | `is_locked` | boolean | 锁定（评论区关闭） |
| 13 | `created_at` | timestamptz | |
| 14 | `updated_at` | timestamptz | |
| 15 | `author_display_name` | text | 作者昵称 |
| 16 | `author_avatar` | text | 作者头像 id |

```ts
const { data } = await supabase.rpc('search_posts', {
  p_query: keyword,
  p_board: board ?? null,
  p_sort: sort,
  p_limit: limit + 1,   // 多取 1 条判断 hasMore
  p_offset: offset,
  p_since: since ?? null,  // 时间筛选的可选下限（ISO 字符串）
  p_until: until ?? null,  // 时间筛选的可选上限（ISO 字符串，不含）
})
```

规则：
- 标题或正文命中（`ilike`）；`%`、`_`、`\` 已转义，搜「100%」不会变成通配符。
- 排除 `is_deleted = true`；**置顶永远排最前**，其次按 `p_sort`，再按 `created_at desc`。
- `p_since` / `p_until` 都是可选的，区间**左闭右开**（`>= since` 且 `< until`）；两个都传 null 时与旧版行为完全一致，旧调用（5 个参数）不受影响。
- 返回**不带** `is_deleted` 列（结果必然是未删的）。

### 4.3 `posts_by_author`

`posts_by_author(p_user_id uuid, p_limit int default 20, p_offset int default 0) returns setof public.posts`

**匿名可调** · 返回与 `posts` 表同构的行（**不含 author 嵌入**，作者信息用 `author_profile` 的结果）

| 入参 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `p_user_id` | uuid | 无（必传） | 作者 user id |
| `p_limit` | int | 20 | 1–50 |
| `p_offset` | int | 0 | |

- 排序：`is_pinned desc, created_at desc`；排除 `is_deleted = true`。
- 注意：这是 `setof posts`，返回数组元素就是 `posts` 行；作者卡片信息请配合 4.4 的 `author_profile` 使用。

```ts
const { data } = await supabase.rpc('posts_by_author', {
  p_user_id: userId, p_limit: limit + 1, p_offset: offset,
})
```

### 4.5 `my_profile`

`my_profile()` —— **仅登录** · 当前用户完整资料（含 role / 封禁信息 / 用户名）

| 返回列 | 类型 | 说明 |
|---|---|---|
| `id` | uuid | 用户 id |
| `display_name` | text | 昵称 |
| `avatar` | text | 头像 |
| `bio` | text | 简介 |
| `role` | `user_role` | `user` / `moderator` / `admin`（前端据此判断管理入口） |
| `is_active` | boolean | 账号是否启用（封禁 = false） |
| `banned_reason` | text | 封禁原因（解封 / 未封禁 = null） |
| `banned_until` | timestamptz | 临时封禁到期时间，NULL = 永久或未封禁 |
| `created_at` | timestamptz | |
| `updated_at` | timestamptz | |
| `username` | text | 当前句柄（`user_handles.is_current`），可能为 null |

**封禁判据（前端 `isBanned` 必须与数据库一致）：**

```ts
const isBanned =
  !profile.is_active &&
  (!profile.banned_until || new Date(profile.banned_until) > new Date())
// is_active=false + banned_until 为空        → 永久封禁
// is_active=false + banned_until 在未来      → 临时封禁（到期自动恢复）
// is_active=false + banned_until 已过期      → 已自动恢复，不再视为封禁
```

数据库侧 `is_active_user()` 用同一判据；封禁用户所有写操作都会被拦（见 4.15 错误文案）。

### 4.8 `vote_post`

`vote_post(p_post_id uuid, p_value smallint)` —— **仅登录** · 点赞 / 踩 / 取消（原子操作）

| 入参 | 类型 | 说明 |
|---|---|---|
| `p_post_id` | uuid | 帖子 id |
| `p_value` | smallint | `1` 赞，`-1` 踩，`0` 取消 |

行为：
- 没有投过 + `1/-1` → 新增投票，对应计数 +1；
- 已有相同值再点 → **取消**（计数 -1，`my_vote = null`）；
- 已有相反值 → 切换（赞 -1 踩 +1 或反之）；
- `0` → 取消（无投票时也安全，幂等）。

返回列（单行数组）：

| 列名 | 类型 | 说明 |
|---|---|---|
| `like_count` | int | 最新点赞数 |
| `dislike_count` | int | 最新踩数 |
| `my_vote` | smallint | 我当前的票：`1` / `-1` / `null`（取消后） |

```ts
const { data } = await supabase.rpc('vote_post', { p_post_id: postId, p_value: 1 })
const { like_count, dislike_count, my_vote } = data[0]
```

错误：「请先登录」「账号当前无法操作」「非法投票」「帖子不存在或已删除」。

### 4.16 `admin_set_active`

|---|---|---|---|
| `p_user_id` | uuid | 无 | 目标用户 |

| `p_reason` | text | null | 封禁原因（**封禁时必填**；解封传 null） |
| `p_until` | timestamptz | null | null = 永久封禁；未来时间 = 临时封禁（到期自动恢复） |

「封禁到期时间必须晚于当前时间」。

## 5. 错误码与前端文案映射

> 常见错误统一用 `error.code` / `error.message` 判断，展示中文。下面这些是已知会出现的：

| 场景 | PG / PostgREST 错误 | 前端建议文案 |
|---|---|---|
| 未登录调仅登录 RPC | `42501` + 「请先登录」 | 直接展示「请先登录」，并引导登录 |

## 6. 注册 / 登录 / 封禁流程（数据库侧约定）

### 6.1 注册（邮箱 + 昵称 + 密码，无用户名登录）

```ts
await supabase.auth.signUp({
  email,
  password,
  options: { data: { display_name: nickname, username?: optional } }, // username 可选
})
```

- 需要在 Supabase Dashboard 关闭 **Confirm email**（Authentication → Providers → Email），否则注册后没有 session。
- 触发器 `handle_new_user`（在 `auth.users` 上）自动：
  1. 写 `profiles`（`display_name` 清洗为 2–20 字符，兜底「新同学」）；
  2. 写 `user_handles`：metadata 里的 `username` 合法且未被占用则用；否则自动生成 `u_` + 8 位十六进制；
  3. 同一事务，失败则注册整体回滚。
- **邮箱前缀不会被拿来当用户名**（含点 / 加号 / 中文 / 太短都会失败），所以句柄一定是合法格式。
- **昵称 / 用户名命中违禁词 → 注册整体失败**。前端注册前先调 `check_banned_word(昵称)`（匿名可用），命中就直接提示换一个，避免只看到 GoTrue 的通用报错。
- 注册后：`user_handles` 有且仅有一行 `is_current = true`（部分唯一索引保证）。

### 6.2 登录后

```ts
supabase.auth.onAuthStateChange(...) 后调 my_profile()：
- profile.role 判断是否显示管理入口；
- isBanned（见 4.5）为 true 时提示原因，写操作会被数据库拦。
```

### 6.3 设管理员（SQL Editor，不经过前端）

```sql
-- 按注册邮箱（推荐）
update public.profiles p
   set role = 'admin'
  from auth.users u
 where u.id = p.id
   and lower(u.email) = lower('you@example.com');

-- 验证
select id, display_name, role from public.profiles where role <> 'user';
```

设置后刷新页面（或重新登录）即可；`role` 不在 JWT 里，所以不需要重新签发 token。

| # | 差异 | 原因 |
